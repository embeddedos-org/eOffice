# Contributing to eOffice

Thank you for your interest in contributing to eOffice! We welcome contributions from the community.

## Getting Started

1. Fork the repository on GitHub
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/eOffice.git`
3. Create a branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Run tests: `npm test`
6. Commit: `git commit -m 'feat: add amazing feature'`
7. Push: `git push origin feature/your-feature-name`
8. Open a Pull Request

## Commit Convention

We use [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` New feature
- `fix:` Bug fix
- `docs:` Documentation changes
- `style:` Code style changes (formatting, etc.)
- `refactor:` Code refactoring
- `test:` Adding or updating tests
- `chore:` Build process or auxiliary tool changes

## Code Style

- TypeScript strict mode
- ESLint + Prettier for formatting
- Component files use PascalCase
- Utility files use camelCase
- CSS classes use Tailwind utilities

## Pull Request Guidelines

- Keep PRs focused and small
- Include tests for new features
- Update documentation as needed
- Ensure CI passes before requesting review

## Reporting Bugs

Please use GitHub Issues with the bug template.

## Feature Requests

Please use GitHub Discussions for feature requests.

## Code of Conduct

Be respectful, inclusive, and constructive. We follow the [Contributor Covenant](https://www.contributor-covenant.org/).
